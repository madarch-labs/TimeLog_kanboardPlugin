# TimeLog

Плагин Kanboard для ручного учёта затраченного времени. Вместо таймера подзадач
используются списания: дата, часы, исполнитель и комментарий. Поле «Затрачено»
задачи рассчитывается как сумма времени подзадач и всех списаний и доступно
только для чтения.

## Возможности

- списание времени из меню и сайдбара задачи;
- редактирование и удаление записей с пересчётом `tasks.time_spent`;
- отчёты по пользователю, проекту и всем проектам/пользователям;
- фильтры по датам, проектам и пользователям, экспорт CSV;
- JSON-RPC API для CRUD и отчётов;
- отключение таймера подзадач и настройки `subtask_time_tracking`;
- перенос существующего ручного `time_spent` в служебные записи при миграции;
- русская локализация.

## Установка

1. Скопируйте каталог `TimeLog` в `kanboard_plugins/` (в контейнере —
   `/var/www/app/plugins`).
2. Убедитесь, что каталог доступен веб-серверу Kanboard.
3. Откройте приложение: плагин автоматически применит схему БД.
4. В «Настройки → Плагины» проверьте, что `TimeLog` включён.

Перед обновлением на рабочей базе сделайте резервную копию БД. Миграция версии 2
переносит разницу `tasks.time_spent - SUM(subtasks.time_spent)` в служебные
записи `timelog_worklogs` и устанавливает `subtask_time_tracking = 0`.

## Отключение

Удалите каталог плагина и перезапустите приложение. Таблица `timelog_worklogs`
остаётся в БД; при необходимости удалите её вручную. После отключения плагина
поле `time_spent` снова станет редактируемым, а таймер подзадач — доступным.

## Права

- `app-user`, участник проекта: создаёт и редактирует списания только за себя в
  задачах своих проектов; видит только свой отчёт.
- `project-manager`: может списывать время за участников своего проекта, видеть
  отчёт проекта и редактировать записи в нём.
- `app-admin`: полный доступ, включая глобальный отчёт и служебные записи
  (`is_system`).

## Отчёты

- `/timelog/user/:user_id` — отчёт пользователя (свой или для администратора).
- `/timelog/project/:project_id` — отчёт проекта (менеджер проекта или админ).
- `/timelog/all` — глобальный отчёт (только администратор).

Фильтры передаются GET-параметрами, поэтому ссылкой можно поделиться. Экспорт CSV
учитывает те же фильтры и права.

## JSON-RPC API

Методы: `createWorklog`, `updateWorklog`, `removeWorklog`, `getWorklog`,
`getTaskWorklogs`, `getWorklogReport`.

С токеном приложения:

```bash
curl -u "jsonrpc:<api_token>" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"createWorklog","id":1,
       "params":{"task_id":123,"user_id":5,"hours":1.5,
                 "work_date":"2026-11-01","comment":"ревью"}}' \
  https://kanboard.example.com/jsonrpc.php
```

С личным токеном пользователя (`users.api_access_token`):

```bash
curl -u "ivanov:<personal_token>" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"createWorklog","id":1,
       "params":{"task_id":123,"hours":1.5,
                 "work_date":"2026-11-01","comment":"ревью"}}' \
  https://kanboard.example.com/jsonrpc.php
```

С личным токеном `user_id` необязателен: по умолчанию используется текущий
пользователь. С токеном приложения `user_id` обязателен. Даты принимаются в
пользовательском формате Kanboard или в ISO (`YYYY-MM-DD`).

## Схема данных

Таблица `timelog_worklogs`:

- `task_id`, `user_id` — задача и исполнитель;
- `work_date` — дата списания;
- `hours` — число больше нуля;
- `comment` — комментарий;
- `is_system` — запись, перенесённая из старого поля «Затрачено»;
- `creator_id` — кто создал запись (может быть `NULL` для системных записей);
- `date_creation`, `date_modification` — служебные метки времени.

Поддерживаются PostgreSQL, MySQL и SQLite.

## Ограничения

- Таймер подзадач отключён; записи в `subtask_time_tracking` больше не создаются.
- Время подзадач остаётся частью итога задачи и редактируется через подзадачи.
- Удаление задачи каскадно удаляет её списания.
- Служебные записи может изменять и удалять только администратор.
